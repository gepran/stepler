## Проверка проектов

На реальном desktop проверено совпадение списка в обеих версиях sidebar,
горизонтальном списке composer и настройках. Проверены добавление до создания
задачи, несколько быстрых операций, избранное, цвет, переименование и удаление.
Данные старого формата нормализуются. Метки активных задач, истории, корзины и
подзадач обновляются вместе; удалённый проект не восстанавливается из старой метки.

Список проектов, цвета и избранное теперь синхронизируются между desktop и iOS
через `users/<uid>/meta/projects`. Операции сохраняются в локальной очереди и
применяются к актуальной версии в транзакции. Повтор после потери подтверждения
не переключает избранное второй раз. История переименований и удалений не даёт
старому устройству восстановить удалённый проект. Явное переименование в ранее
удалённое имя снова делает его доступным. В существующем web-клиенте нет полного
редактора метаданных проектов; он получает метки задач.

## Дополнительные исправления после полного прогона

- Независимые правки текста, выполнения, приоритета, проектов и подзадач теперь
  объединяются относительно общей исходной версии. Запись в Firestore выполняется
  транзакцией. Удаление подзадачи и окончательное удаление задачи защищены от
  запоздалого редактирования. При конфликте одного и того же поля действует
  последняя успешно записанная правка; история для ручного разрешения не добавлена.
- Офлайн-выполнение подзадачи в web сохраняется как отдельная операция. После
  подключения она изменяет только выполнение нужного ребёнка в актуальном массиве,
  сохраняя добавления, текст и вложения с другого устройства. Очередь переживает
  перезагрузку страницы и разделена по аккаунтам.
- Desktop хранит отдельные локальные профили аккаунтов. Устаревший renderer не
  может сохранить предыдущий аккаунт после переключения. Черновики, preview и
  состояние напоминаний очищаются. Ошибка записи настроек отклоняет переключение
  и сохраняет текущие задачи; это проверено искусственным отказом диска.
- CSS snapping в редакторе напоминания мог менять минуту `00` на `01` сразу после
  открытия. Исправлено смещение области snapping; тест дожидается её стабилизации.
- iOS сохраняет локальные данные и вложения с защитой файлов, раздельно для
  гостя и каждого аккаунта. Неудачная запись не очищает черновик и не оставляет
  частично сохранённую задачу. Импорт переносит цвета/избранное проектов;
  вложения ограничены собственным путём аккаунта и размером менее 25 МБ.
- Нативное расписание уведомлений обновляется последовательно, в том числе при
  смене аккаунта. Идентификатор успешно созданного Calendar event сохраняется до
  следующей внешней операции, чтобы её ошибка не создавала дубликаты при повторе.

Общая команда desktop/web/Firebase: `npm run test:all`. Она запускает lint,

Desktop-сценарии проверяют совпадение всех списков проектов, быстрые изменения,
редактирование текста, выполнение, приоритет, Drag and Drop, подзадачи,
напоминания, поиск через фильтры, корзину, восстановление и окончательное удаление,
фильтр упоминаний, вставку картинки и ошибку записи вложения с успешным повтором.
Проверены ограничение IPC, доступ из чужого окна, обход пути вложения,
авторизация API, блокировка браузерных запросов и выключение API без перезапуска,
изоляция аккаунтов и отказ записи при переключении.

Firestore-тесты проверяют чужой аккаунт, поддельное принятие приглашения,
настоящий цикл приглашения/принятия/упоминания, атомарную совместную правку,
отзыв доступа, конкурентные транзакции, метаданные проектов, офлайн-подзадачи
и неизменяемую личность. Storage-тест проверяет upload/read/delete владельца,
запрет чужого аккаунта, неправильного пути и файла 25 МБ или больше.

Тесты используют временные локальные профили и только loopback emulators с
`demo-stepler-review`. Они не входят в личные аккаунты и не создают production
задачи. Недоступность эмуляторов считается ошибкой, а не пропуском тестов.

## iPhone

Установлен нативный SwiftUI app: задачи/история/подзадачи, проекты,
редактирование/приоритет/выполнение, перестановка, вложенность и продвижение,
напоминания, файлы/фото/вставка, корзина, JSON import/export, Firebase sync,
Google/email sign-in, контакты и упоминания. Calendar и Apple Reminders включаются
в Settings. Нативный клиент сохраняет неизвестные desktop-поля, включая Jira,
но собственного Jira OAuth/редактора не добавляет.

Финальный подписанный build **1.3.13 (1)** установлен и успешно запущен через
`devicectl` на iPhone 13. После запроса разблокировки владелец разблокировал
телефон; повторный запуск финальной версии подтверждён успешным ответом CoreDevice.
Для синхронизации: Settings → Sign in → Continue with Google, тот же аккаунт,
что на desktop. Гостевые задачи остаются в отдельном профиле; экспорт/импорт
позволяет явно перенести их в аккаунт.

Это development installation. Текущий provisioning profile действует до
**9 октября 2026, 13:11:55 UTC**; после этого нужна повторная сборка/установка.
Это не публикация в App Store или TestFlight.

## Границы подтверждённой проверки

1. Настоящий вход в личный Google/Firebase аккаунт, доставка уведомления при
   заблокированном устройстве, Google Calendar, Jira и Apple Calendar/Reminders
   с личными данными не выполнялись автоматически. Код и изолированные тесты
   проверены; полноценный внешний прогон требует аккаунтов и разрешений ОС.
2. Windows/Linux, desktop-установщики, обновление уже установленного приложения,
   все типы preview-файлов и iPad не проходили полный ручной прогон.
3. Очистка корзины не является гарантированным стиранием из резервных копий и
   Storage. Исправлено возвращение задачи при синхронизации; отдельная политика
   очистки резервных копий/неиспользуемых файлов не реализована.
4. Нулевой npm audit относится к npm-зависимостям, а не к Swift packages.
   Отрицательные тесты подтверждают проверенные ограничения доступа, но не
   доказывают отсутствие любой возможной уязвимости.
